# Conversation message safety

`POST /api/v1/conversations/:conversation_id/messages` keeps the existing participant authorization, message DTO, transaction, and notification behavior. Before the transaction, the service combines the deterministic classifier with Gemini when `AI_ENABLED=true` and `GEMINI_API_KEY` is configured. The deterministic result is always retained; Gemini cannot clear a rule-based finding. Provider failure, timeout, quota exhaustion, invalid output, disabled configuration, or missing credentials fall back to the rule-based result, so a valid message can still be stored.

The response and message history retain `sender_id`, `body`, `created_at`, and `moderation`, with `moderation.source` (`gemini` or `rule_based`) and `moderation.status` (`AI_COMPLETED` or `RULE_BASED_FALLBACK`). The `Message.moderationSource` Prisma field records provenance; existing rows default to `RULE_BASED`. Severity uses the existing Prisma `FlagSeverity` values, and reasons use the controlled moderation reason contract. Flags are advisory, not a finding of fraud.

Only the authorized message body is sent for classification. Email addresses, phone-like numbers, 4–20 digit codes/account identifiers, URL paths, and URL query strings are masked; a URL hostname remains for risk context. No history, account data, seller private address, tokens, credentials, or database data is added. Gemini calls happen before the database transaction, are bounded by the configured timeout/token limits, use one SDK attempt, and are rate-limited per account. Successful classifications are briefly coalesced/cached per process by an opaque HMAC of account, conversation, and message content to reduce duplicate calls during retries. The HMAC secret is randomly generated once at process start and never persisted or logged; the bounded cache is intentionally process-local. This is not cross-instance idempotency; a persistent client idempotency contract is still needed to guarantee replay behavior across server restarts or replicas. When the in-flight classification cap is reached, messages use the deterministic fallback. Message contents and provider errors are not logged by this integration.

## Privacy and operational requirements

AI is opt-in at the server configuration level and defaults off. Do not enable it for real users until the product has an appropriate privacy disclosure, legal/product approval for external processing, and a user-facing consent decision where required. Local in-memory rate limits are process-scoped; production multi-instance deployments need a shared rate-limit store and operational monitoring that does not log message contents. No live Gemini call is made by tests.
